# Pilot Readbacks

A pilot readback is an acknowledgement of an instruction or clearance previously issued by ATC.

A readback is not a new request.

A pilot may use different wording to acknowledge the same instruction.

Examples of readbacks include:

- "Cleared for takeoff runway 23, LV-INQ."
- "Roger, cleared for takeoff runway 23."
- "Received clearance for takeoff runway 23."
- "Reading back, cleared for takeoff runway 23."
- "Wilco."

The controller should recognize the meaning of the transmission rather than requiring a specific keyword such as "readback".

## Correct readback

If the pilot correctly acknowledges an instruction or clearance that ATC has already issued:

- Treat the instruction as acknowledged.
- Do not repeat the same instruction.
- Do not issue the same clearance again.
- Continue with another instruction only if one is operationally necessary.

If no further response is required, output:

[NO RESPONSE]

## Readback versus request

A transmission such as:

"Cleared for takeoff runway 23, LV-INQ"

is normally a readback if ATC has just issued that clearance.

A transmission such as:

"Requesting clearance for takeoff runway 23, LV-INQ"

is a request and requires ATC to decide whether the clearance can be issued.

The conversation history should be used to distinguish these cases.

## Incorrect or incomplete readbacks

If a pilot readback conflicts with the previous ATC instruction, do not treat it as a valid acknowledgement.

Issue the appropriate correction or clarification.

Example:

ATC:
"Cleared for takeoff runway 23."

Pilot:
"Cleared for takeoff runway 14."

The pilot has not correctly read back the clearance. The controller should correct the misunderstanding.
